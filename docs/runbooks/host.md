# eris host

Alerts: `HostRootDiskAlmostFull`, `HostRootDiskFull`, `HostDiskWillFillIn24h`, `HostOutOfMemory`,
`HostHighCpuLoad`, `HostRebooted`, `GpuHot`, `GpuMemoryNearlyFull`, `GpuUnavailable`.

## Disk full

```sh
df -h /
sudo du -xh --max-depth=1 /home/jeff/volumes | sort -h | tail
docker system df
```

Safe to reclaim:

```sh
docker image prune -a -f --filter until=168h     # unused images older than a week
docker builder prune -f
sudo journalctl --vacuum-size=500M
```

**Not** `docker system prune` / `docker container prune`: they delete the job containers.
Usual growers: `volumes/ollama` (models: `docker exec ollama ollama rm <model>`),
`volumes/monitor/prometheus`, `volumes/photon`, container logs (capped at 3×20 MB each by
`/etc/docker/daemon.json`).

## Memory / CPU

```sh
docker stats --no-stream --format 'table {{.Name}}\t{{.CPUPerc}}\t{{.MemUsage}}' | sort -k3 -h | tail
```

Usual suspects: Ollama or Immich ML holding a model, the Immich/Photon importers, a game
server. `docker restart <name>` frees it.

### Memory limits

Since 2026-10-19 the big, spiky containers have a `mem_limit` well above their observed peak
(Immich photos 14g, Ollama 12g, Photon 7g, flightdensity-public 7g, Immich private 6g,
SABnzbd/Immich ML 5g, Jellyfin/Stash/collector 4g, Open WebUI 3g, FlareSolverr 2g,
games 5–6g, Minecraft 18g). Everything else is unlimited. Core services (Caddy, AdGuard,
Authentik, Home Assistant, Mosquitto, Z-Wave, Matter) have `oom_score_adj: -500`, so the
kernel kills something else first.

- `ContainerNearMemoryLimit` (>90% for 5 min) → check whether it's real work (an Immich import,
  a big model). If so, raise the limit in the compose file and apply it without a restart:
  `docker update --memory 16g --memory-swap 32g <name>`.
- `ContainerOomKilled` → the limit was hit and the container restarted. Raise the limit the
  same way, or find the leak.
- Peaks to size from: Grafana, or
  `max_over_time(container_memory_working_set_bytes{name="<name>"}[30d])` in Prometheus.

## GPU

```sh
nvidia-smi
```

If `nvidia-smi` errors after a kernel update ("couldn't communicate with the driver"),
the driver didn't build for the new kernel: reboot once; if it persists,
`sudo apt install --reinstall nvidia-dkms-<version>` (version from `dpkg -l | grep nvidia-dkms`).
Containers using the GPU: ollama, whisper, immich ML (both), lora-studio.

**`GpuUnavailable`, or `bin/health` says "GPU lost inside": host `nvidia-smi` works but
containers say `Failed to initialize NVML: Unknown Error`.** A systemd reload rebuilt the
containers' device allow-lists without the NVIDIA devices (systemd cgroup driver, cgroup v2).
Docker can't re-grant a device to a running container, so restart each one:

```sh
docker restart nvidia-gpu-exporter whisper ollama immich_machine_learning immich_photos_machine_learning jellyfin
docker exec ollama nvidia-smi -L   # should list the GTX 1080
```

Prevention (both parts needed):
- Every GPU service requests the GPU via **CDI**, not the legacy hook (`driver: nvidia` / `gpus: all`):
  ```yaml
  deploy: { resources: { reservations: { devices: [ { driver: cdi, device_ids: [nvidia.com/gpu=all], capabilities: [gpu] } ] } } }
  ```
  The legacy hook grants the device behind systemd's back, so a reload drops it. CDI puts it in the
  container spec. Spec: `/var/run/cdi/nvidia.yaml`, regenerated by `nvidia-cdi-refresh` after driver updates.
  Check: `systemctl show docker-$(docker inspect -f '{{.Id}}' ollama).scope -p DeviceAllow | grep 195` must list `/dev/char/195:*`.
- `/dev/char` symlinks for the NVIDIA devices, recreated at boot by
  `/etc/udev/rules.d/71-nvidia-dev-char.rules` (`nvidia-ctk system create-dev-char-symlinks --create-all`).
Happened 2026-10-24 (~28 h unnoticed, before this alert existed).

## Rebooting eris (planned)

1. `bin/health`. Don't reboot while borgmatic runs (02:00–02:15) or while a NAS disk operation runs.
2. `sudo apt update && sudo apt full-upgrade` (optional), then `sudo reboot`.
3. At boot, `nas-wait.service` holds Docker for up to 5 minutes until the NAS shares mount.
   Containers come back by their restart policy.
4. After ~5 minutes: `bin/health`. If `InfraContainerGone` fires but everything is up,
   it's the cAdvisor boot race: `docker restart cadvisor`.

## eris won't boot / is unreachable

Plug in a monitor. If the disk or OS is gone, see [disaster-recovery.md](disaster-recovery.md).
While eris is down: **LAN DNS goes down too** (the router points at AdGuard on eris).
Set the router's DNS to `1.1.1.1` so the household keeps internet.
